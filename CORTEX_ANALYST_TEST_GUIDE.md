## 🚀 Next Steps: Live Testing

### 1. Upload Updated Semantic Model to Snowflake

```sql
-- In Snowflake SQL worksheet:
USE DATABASE MDM_CUSTOMER_MATCHING;
USE SCHEMA PUBLIC;

-- Upload the updated semantic model file to the stage
-- Use Snowsight UI or Snow CLI:
```

**Option A: Snowsight UI**
1. Go to Data → Databases → MDM_CUSTOMER_MATCHING → PUBLIC → Stages → SEMANTIC_MODELS
2. Click "Upload Files"
3. Select `customer_matching_semantic_model.yaml` (this will overwrite the existing file)

**Option B: Snow CLI**
```bash
snow stage copy file://./customer_matching_semantic_model.yaml @MDM_CUSTOMER_MATCHING.PUBLIC.SEMANTIC_MODELS --overwrite
```

### 2. Verify Upload
```sql
-- Check the file is uploaded
LIST @SEMANTIC_MODELS;

-- Test reading the semantic model
SELECT $1 FROM @SEMANTIC_MODELS/customer_matching_semantic_model.yaml LIMIT 5;
```

### 3. Test Cortex Analyst Integration

**Access the Chat View:**
- Navigate to `http://localhost:8502` (or your Streamlit port)
- This should show the "Customer Matching Assistant" with "Powered by Snowflake Cortex Analyst & Semantic Model"

**Test These Queries in Order:**

1. **Basic Semantic Model Test:**
   ```
   "Which test customers are exact matches?"
   ```
   - Should call Cortex Analyst with semantic model
   - Should return SQL generated by Cortex Analyst
   - Should show results in a table

2. **New Verified Query Test:**
   ```
   "Show me the top 5 matches for TEST_0FCD7224E341"
   ```
   - Should use the new `top_matches_for_customer` verified query
   - Should show similarity scores and match categories

3. **Category Breakdown Test:**
   ```
   "What's the breakdown of match categories?"
   ```
   - Should leverage semantic model dimensions
   - Should show counts for EXACT, VERY_CLOSE, etc.

4. **Flexible Natural Language Test:**
   ```
   "How many test customers have similarity above 95%?"
   ```
   - Should demonstrate Cortex Analyst's natural language understanding
   - Should generate appropriate WHERE clause with similarity_percentage

### 4. Expected Behavior

**Success Indicators:**
- ✅ Queries return SQL generated by Cortex Analyst (not hardcoded)
- ✅ Results are displayed in tables
- ✅ No error messages about semantic model file
- ✅ Responses are more flexible and natural than before

**Fallback Indicators (Expected if Cortex Analyst fails):**
- ⚠️ Warning message: "Cortex Analyst SQL function failed, using fallback"
- ⚠️ Still gets results but uses predefined SQL queries

**Error Indicators (Need Investigation):**
- ❌ "Semantic model file not found" errors
- ❌ Complete failure to respond to queries
- ❌ Streamlit crashes or connection errors

### 5. Troubleshooting

**If Cortex Analyst Fails:**
1. Check that CORTEX_USER role is granted to your user:
   ```sql
   SHOW GRANTS TO USER <your_username>;
   ```
2. Verify semantic model file path:
   ```sql
   SELECT $1 FROM @MDM_CUSTOMER_MATCHING.PUBLIC.SEMANTIC_MODELS/customer_matching_semantic_model.yaml LIMIT 1;
   ```

**If Streamlit Fails:**
1. Check terminal for error messages
2. Verify Snowflake connection is working
3. Test with simple query first
